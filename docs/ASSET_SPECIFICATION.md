# 资产规范草案

## 1. 通用坐标与命名

- 引擎单位：1 单位 = 1 米。
- 坐标：Y 向上，X 向右，跑酷前进方向为 -Z。
- 角色原点：双脚落地点中心；默认站姿面向 -Z。
- 文件和资源 ID 使用小写英文、数字和连字符，例如 `nailong-run.glb`。
- 展示名称允许中文，但逻辑不得依赖展示名称。

## 2. 正式角色交付门槛

在建模前必须先确认：正面、严格侧面、严格背面、统一比例标尺、颜色板和关键表情。

模型要求：

- 连续曲面雕刻/拓扑，禁止以球体、胶囊体、圆锥体拼装冒充最终模型。
- 统一 UV；材质数量尽量控制在 1–3 个。
- 主角 LOD0 建议 6–9 万三角形，另交 LOD1/LOD2；最终以浏览器实测为准。
- 2K 主贴图为默认上限；眼睛等需要特写的区域可单独评估。
- GLB 中不得包含未使用网格、相机、灯光或重复材质。

骨骼与动画最低集合：

```text
idle
run
jump_start
jump_loop
land
slide
hit
celebrate
look_back      洞洞幺紧追段使用
portal_escape  洞洞幺传送门逃脱
```

动画需可循环的必须无可见跳帧；位移默认由游戏控制器驱动，不在循环动画里累计根运动。

## 3. 世界资产

- 每个世界独立目录，拥有自己的色板、光照、雾、天空、地标、NPC、障碍、音乐和掉落物。
- 路线段采用可拼接模块，但轮廓、材质和动态事件必须体现该世界的独特语言。
- 远景、中景、近景分层；路线可读性优先于装饰密度。
- 重复植被和小道具使用实例化；大地标保留独立动画和交互能力。
- 第三方角色和场景内容必须可整体替换，不得嵌入核心包。

## 4. UI 资产

- 禁止 emoji 作为正式图标。
- 图标由统一 SVG 源文件导出，保持相同线宽、圆角、透视和珠光材质语言。
- 每个交互控件至少定义：默认、悬浮、按压、禁用、解锁、可领奖状态。
- 正文、数值、标签建立固定字号阶梯；不把文字烘焙进图片。
- 颜色和文字对比度需要在明亮场景与深色场景中分别验证。

## 5. 导入验收

- 比例、朝向、原点正确。
- 法线、切线、UV 和透明排序无异常。
- 动画名称、时长、循环与根运动正确。
- 纹理色彩空间正确：颜色贴图为 sRGB，数据贴图为线性。
- 低、中、高画质均能正确显示。
- 资产来源、作者、授权和版本记录完整。
